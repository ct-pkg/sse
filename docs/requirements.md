# ct-sse 需求规约

> 状态：需求层梳理完成，**未立项**。
> 依据：[proposal.md](proposal.md)（提案原文，本文不修改其正文）、[analysis.md](analysis.md)、[design.md](design.md)、[README.md](../README.md)。
> 边界：本文只做需求层判定。不含设计选型、实现代码、phase 卡、roadmap、阶段切分。

## 0 阅读约定

- 需求编号：`R-<组>-<序号>`，组为 A（协议解析）、B（事件暴露与回调）、C（生命周期与内存）、D（错误与状态）、E（工程与交付）。
- 阻塞等级只取三值：
  - **已支持**：现有 CT 能力直接够用；
  - **软阻塞**：语言缺某能力，但有不改语言的绕行方案，绕行已写在条目里；
  - **硬阻塞**：当前 CT 无法实现该条，必须改语言或改需求。
- 判据只接受两类：**可执行**（给定输入 → 期望输出，可用用例断言）或**可核对**（可逐条人工/脚本比对）。**"能编译通过"不作为任何条目的判据。**
- 术语：**事件块** = 两次空行之间的一段输入；**分发** = 触发一次事件回调；**持久值** = 跨事件保留的 parser 状态。

## 1 一句话需求

把可能被任意分片的 WHATWG SSE 字节流，增量解析成事件回调；事件字段零拷贝借用 parser 缓冲，回调返回即失效；协议非致命情况忽略，资源与回调错误可通过 `has_error()` 查询；本包只做解析，不做传输、语义与重连。

## 2 使用边界

| 角色 | 说明 |
| --- | --- |
| 上游 | 任意分片的字节块（`feed(chunk, len)`），不保证按行/按事件对齐 |
| 下游 | 具名函数或函数指针形式的事件回调（`SseEventCb`） |
| 不属于本包 | HTTP 传输（ct-http）、LLM 协议语义（ct-llm-sse）、重连策略（内核）、事件路由/多订阅（事件总线） |

## 3 需求条目

### 3.1 A 组：协议解析

| 编号 | 要解决的问题 | 验收判据 | 非目标 | CT 依赖/阻塞 |
| --- | --- | --- | --- | --- |
| R-A-01 | TCP 分片会把一行切成两半；parser 必须跨 `feed` 调用保留半行，不能按 chunk 边界丢数据或提前解析 | ① `"data: hel"` + `"lo\n\n"` 两次 feed → 回调 1 次，`ev->data == "hello"`；② 同一输入逐字节 feed 与整块 feed 的事件序列、回调次数、各字段值完全一致 | 不做网络读取与分片调度；不保证 `feed` 线程安全 | 已支持 |
| R-A-02 | WHATWG 允许 CRLF / 单 CR / 单 LF 三种行结束；CRLF 可能跨 chunk 断开 | ① `"data: a\r\n\r\n"`、`"data: a\r\r"`、`"data: a\n\n"` 各触发 1 次，data 均为 `a`；② 在 `\r` 与 `\n` 之间切开（`"data: a\r"` + `"\n\r\n"`）不得多计分发次数、不得产生额外空事件 | 不做字符编码转换 | 已支持 |
| R-A-03 | 行首 `:` 是注释，必须整行忽略，即使行内还有冒号 | `":x: data: y\n\ndata: z\n\n"` 只触发 1 次且 `ev->data == "z"`；注释行不改变 data/event/id/retry 任一状态，`has_error() == 0` | 不保留注释内容、不回调注释 | 已支持 |
| R-A-04 | 字段名与值按**第一个**冒号切分；值前**只去掉一个**空格；无冒号行等价于"字段名 + 空值"；未知字段忽略 | ① `"data:  x\n\n"`（两个空格）→ `ev->data == " x"`；② `"data\n\n"` 等价 `"data:\n\n"`；③ `"foo: bar\n\n"` 触发 0 次且 `has_error() == 0`；④ `"Data: x\n\n"` 不产生 data（字段名大小写敏感） | 不做字段名规范化/别名 | 已支持 |
| R-A-05 | 多行 data 用 LF 连接；分发时**只去掉一个**末尾 LF，不做 while-trim | ① `"data: YHOO\ndata: +2\ndata: 10\n\n"` → 1 次回调，`data_len == 10`，`ev->data == "YHOO\n+2\n10"`；② `"data: a\ndata:\n\n"` → `ev->data == "a\n"`（中间的 LF 保留） | 不解析 data 内容语义；不裁剪其他空白 | 已支持 |
| R-A-06 | 提案用"data 缓冲为空则不分发"，但 `data:` 会先落入一个 LF，trim 后为空串仍应分发**空 data 事件**；判定必须以"本事件块是否出现过 data 字段"为准 | ① `"data:\n\n"` → 触发 1 次，`data_len == 0`，data 指向空串；② `"event: ping\n\n"` → 触发 0 次，且 event 缓冲已被清空（随后 `"data: x\n\n"` 的 event 为 `message`）；③ `"id: 7\n\n"` → 触发 0 次 | 不把空 data 视为错误；不特殊处理空事件 | 已支持 |
| R-A-07 | event 指定事件类型；缺省或空值回落 `message`；dispatch 后必须清空，不跨事件 | ① `"event: ping\ndata: x\n\n"` → `ev->event == "ping"` 且 `is_message() == 0`；② 随后 `"data: y\n\n"` → `ev->event == "message"` 且 `is_message() == 1`；③ `"event:\ndata: x\n\n"` → `message` | 不做事件类型路由/订阅 | 已支持 |
| R-A-08 | id 是流级持久 lastEventId：跨事件保留、空值清除、值含 NUL 时整条忽略、取值点为 dispatch 时刻 | ① `"id: 1\ndata: a\n\n"` → `ev->id == "1"`；随后 `"data: b\n\n"` → `ev->id` 仍为 `"1"`，`last_event_id() == "1"`；② 在下一块前插入 `"id:\n\n"` → 之后 `ev->id == NULL`、`has_id() == 0`、`last_event_id() == NULL`；③ id 值含 `\0` 时整条 id 行忽略，前值保留；④ id 行出现在上一块空行之后时，不影响已分发事件的 `ev->id` | 不生成 `Last-Event-ID` 请求头（ct-http 负责） | 已支持 |
| R-A-09 | 提案把 retry 当"只在本事件有效"并在 dispatch 后清零，与 WHATWG 的流级重连时间冲突 | ① `"retry: 3000\ndata: a\n\n"` 后 `retry_hint() == 3000`；随后 `"data: b\n\n"`（不设 retry）后仍为 3000；② `retry: 3x` / `retry: -1` / `retry:` / 超出 `INT_MAX` 均不更新，保持前值；③ `SseEvent.retry` 等于 dispatch 时刻的持久值，`has_retry()` 等价于该值非 0 | 不实现退避算法；不把 retry 用于本包内重连 | 已支持 |
| R-A-10 | 空行是事件边界；无 data 字段的块不分发，但事件类型缓冲仍按规范在分发时机清空 | ① `"\n\n\n"` 连续空行 → 0 次回调、`has_error() == 0`；② `"data: 1\n\ndata: 2\n\n"` → 2 次且顺序正确；③ 无 data 块后紧跟的事件其 event 为 `message` | 不合并空事件、不排队延迟分发 | 已支持 |

### 3.2 B 组：事件暴露与回调

| 编号 | 要解决的问题 | 验收判据 | 非目标 | CT 依赖/阻塞 |
| --- | --- | --- | --- | --- |
| R-B-01 | 回调内需要可读的事件视图：event / data / data_len / id / retry，且 data 可含 NUL | ① 结构字段与提案 §3 一致；② `data` 含 `\0` 时 `data_len` 仍覆盖全部字节（不依赖 `strlen`）；③ `has_id()` / `has_retry()` / `is_message()` 在 R-A-07/08/09 的字段取值表上逐行一致（可列真值表核对） | 不提供 data 的字符串长度语义；不让 `SseEvent` 拥有内存 | 已支持 |
| R-B-02 | parser 需要一个事件消费点，且回调形态必须是具名函数/函数指针（SH-67：闭包字面量不可直接当 C 回调） | ① `on_event(cb, ud)` 后每个分发事件恰好调用 `cb` 一次，`ud` 为注册时原值；② 未注册回调时的行为按冻结口径（Q-10）可测：静默丢弃 → `feed` 返回 0 且 `has_error() == 0`；报错 → `feed` 返回 -1 且 `has_error() == 1` | 不支持多订阅者、闭包字面量、事件路由 | 已支持（L11 函数指针）；闭包限制属已知约束，不阻塞 |
| R-B-03 | 回调返回非 0 时的中断语义必须唯一，不能与"返回事件数"混用 | ① 回调返回 1 → `feed` 返回 -1、`has_error() == 1`、`error_msg() != NULL`，本块剩余字节不再解析，后续事件不分发；② 回调返回 0 → `feed` 返回 `>= 0` 的事件数、`has_error() == 0`；③ 中断后再次 `feed` 的行为按 Q-08 冻结口径可测 | 不定义回调异常的栈展开 | 已支持 |
| R-B-04 | `SseEvent` 字段借用 parser 缓冲，回调返回即失效；语言不做借用检查，文档与负例是唯一防线 | ① README 逐条列出提案 §3 的五条所有权契约（可人工核对条目齐备）；② 负例可执行：回调保存 `ev->data` → 喂第二个事件 → 断言旧指针内容已变、且与新事件指针相同（证明复用而非副本）；③ ASan 构建下：保存指针 → `delete` parser → 读该指针，用例期望 ASan 报出 heap-use-after-free | 不引入借用检查；不保证回调返回后指针可用 | **软阻塞**（无借用检查；靠契约 + 负例，不改语言即可） |
| R-B-05 | 调用方若需跨回调保留事件，必须显式拷贝；无标准手段时每个消费者各写一套易错 | 若纳入：`sse_event_copy(ev)` 返回独立拥有的事件副本，parser 后续 `feed`/`delete` 后副本内容不变；副本有明确释放规则，ASan 下无泄漏 | 不提供引用计数/GC 自动管理 | 已支持（是否纳入见 Q-01） |

### 3.3 C 组：生命周期与内存

| 编号 | 要解决的问题 | 验收判据 | 非目标 | CT 依赖/阻塞 |
| --- | --- | --- | --- | --- |
| R-C-01 | L5 下工厂返回值不能写 `own`，需要明确可用的构造/销毁方式 | ① `SseParser::new()` 返回可用实例，`new()` 对 `calloc` 失败返回 0；② `delete p` 后内部五块缓冲全部释放（ASan/valgrind 无泄漏）；③ README 明确"`new()` 返回裸指针，调用方负责 `delete`" | 不提供 `own` 返回值；不做引用计数 | 已支持（L5 包层适配：显式 `delete`） |
| R-C-02 | 所有内部缓冲由 parser 独占，`drop` 负责释放；`_current` 是借用视图不得单独释放 | ① `drop` 只释放 line / data / event / last_event_id / error_msg 五块；② "注册回调 + 已分发事件 + 含错误文本"路径下 `delete`，ASan 无 double-free / leak；③ `SseEvent` 无 `Drop`，不被递归清理（可核对生成头或运行时无二次释放） | 不做跨 parser 共享缓冲 | 已支持（显式 `impl Drop` 不生成字段递归 glue） |
| R-C-03 | 单行无限增长会打穿内存，需要可配置上限 | ① 默认上限 65536 生效，超限 `feed` 返回 -1、`has_error() == 1`，错误文本含实际上限数值；② `max_line_bytes(n)` 后，长度 `n-1` 内容行可解析，长度 `n` 内容行被拒（n 的确切含义见 Q-03） | 不限制事件 data 总量（见 R-C-04） | 已支持 |
| R-C-04 | 提案只有行上限，没有事件级 data 上限；恶意流可用无限 data 行持续累积 | 若纳入：设定上限后，超限事件返回 -1、`has_error() == 1`，且连续超限输入下进程内存不持续增长（以分配计数或 RSS 核对） | 不限制单条流的总长度 | 已支持（是否本期见 Q-05） |

### 3.4 D 组：错误与状态

| 编号 | 要解决的问题 | 验收判据 | 非目标 | CT 依赖/阻塞 |
| --- | --- | --- | --- | --- |
| R-D-01 | 协议非致命情况必须忽略且不报错；资源耗尽与回调中断才置错误 | ① 未知字段、非法 retry、注释行、非法 id 之后 `has_error() == 0` 且 `error_msg() == NULL`；② 行超限 / OOM / 回调中断后 `has_error() == 1` 且 `error_msg() != NULL` | 不提供错误码枚举（本期只有整型标志 + 文本） | 已支持 |
| R-D-02 | 错误文本是否稳定影响测试写法与调用方处理 | 三类错误各产出一条非空文本，内容与提案 §7 表一致（行超限文本含实际上限、OOM、回调中断）；比对方式（精确 / 前缀）按 Q-07 冻结口径 | 不做错误国际化、不做错误分类码 | 已支持 |
| R-D-03 | 流结束需要处理残留半行与未分发 data，否则最后一条事件丢失 | ① `"data: a"`（无结尾换行）+ `finish()` → 1 次事件，data 为 `a`；② `"data: a\n"` + `finish()` → 1 次；③ 空 parser + `finish()` → 0 次、无错误；④ `finish()` 返回值与 `feed` 同口径（次数 / -1），具体见 Q-06；⑤ `finish()` 不隐式 `reset`、不隐式 `delete` | 不自动关闭/释放 parser | 已支持 |
| R-D-04 | 调用方需要读取持久 lastEventId 与重连建议，用于跨流重连 | ① 无 id 时 `last_event_id() == NULL`，有 id 时返回持久值且跨事件不变；② 无 retry 时 `retry_hint() == 0`，有 retry 时返回持久值；③ 返回值在 parser 生命周期内有效，`delete` 后失效（文档写明） | 不返回副本；不负责生成请求头 | 已支持 |
| R-D-05 | 复用 parser 处理新流，同时保留重连所需状态 | ① `reset()` 后行缓冲、data、event、errors、`_saw_cr` 清零；② `last_event_id` 与回调注册保留；③ `reset()` 后喂新流不携带上一流的半行与事件；④ `max_line_bytes` 配置保留；⑤ `_retry` 是否清空按 Q-04 冻结口径 | 不释放缓冲（保留容量）；不重置配置 | 已支持 |

### 3.5 E 组：工程与交付

| 编号 | 要解决的问题 | 验收判据 | 非目标 | CT 依赖/阻塞 |

| R-E-01 | `pub struct` 的 impl 方法全部进生成头，`_xxx` 只是命名约定；不冻结公开面就等于没有 API 边界 | ① 生成头导出的函数符号与冻结清单**完全一致**（可脚本比对导出符号表）；② 清单外 helper 不出现在头文件或公开文档中 | 不引入方法级私有（语言不支持） | **软阻塞**（无方法可见性；用 `.ct` 内 `static` 自由函数绕行即可，见 Q-02） |
| R-E-02 | 分析结论是本包不需要新增语言能力；同时文件作用域 `_` + 小写是 C 保留形态 | ① 需求文档中不存在"需要 CT 新增某能力"的条目（可勾选核对）；② 文件作用域函数名不以 `_` + 小写开头（可 grep 核对）；③ `#include` 只出现在 `.ct`，不落入生成 `.h` | 不申请借用检查、方法级私有、工厂 `own` | 已支持 |
| R-E-03 | 借用/所有权是契约不是编译器检查，文档是唯一防线 | README 至少含：五条所有权契约、公开 API 清单、`feed`/`finish` 返回值契约、`max_line_bytes(n)` 的 `n` 含义、`reset()` 保留项、错误文本表；逐条可人工核对 | 不做教程站/用户手册 | 已支持 |
| R-E-04 | chunk 回调驱动 `feed`，错误需要能通知传输层中断 | 提供集成示例（非本包实现），展示 chunk 回调中 `feed < 0 → return 1` 中断；示例可运行，或（ct-http 未就绪时）以桩函数核对调用序列与中断路径 | 不改 ct-http；不实现 HTTP 传输/重连 | **软阻塞**（依赖外部 ct-http 可用性；不阻塞解析包本体） |
| R-E-05 | 协议正确性必须可执行验收，不能只靠人读文档 | ① 提案 §10 的 WHATWG 示例 `"data: YHOO\ndata: +2\ndata: 10\n\n"` 作为用例跑通；② §5 的 19 项协议核对各自至少一条正例或负例；③ 每个用例写明期望（回调次数 / 字段值 / `has_error`） | 不以性能基准作为验收门槛 | 已支持 |

## 4 评估判定"原提案不成立、必须先改"的四处

| # | 原提案 | 判定依据 | 改后口径 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | `int _set_error(char *fmt, ...)` 作为 `SseParser` 方法 | CT 支持用户定义变参函数与 `va_list`/`vsnprintf`，但 struct 方法（含固有 impl）带 `...` 被硬拒（analysis §2 #1） | 错误格式化改为 `.ct` 内文件作用域 `static int sse_set_error(SseParser *p, char *fmt, ...)`；`impl SseParser` 内不出现变参方法；`error_msg()` 保持固定参数 | **已定**（截断策略、错误缓冲归属属设计层） |
| 2 | `_ensure` / `_push_char` / `_push_str` / `_process_line` / `_handle_field` / `_dispatch_event` / `_set_error` 视为私有 | 同一 `.h.ct` 内 `pub struct` 的 impl 方法全部进生成头，`_xxx` 只是命名约定（analysis §2 #2、§3） | 需求层固定"公开 API 面必须最小且可枚举"：公开面只含构造 / 配置 / `feed` / `finish` / 查询 / `reset`；helper 不得进入公开面 | **已定（口径）**；具体清单见 Q-02 |
| 3 | `retry` "只在当前事件有效"，dispatch 后清零 | WHATWG 的 reconnection time 是流级状态、跨事件保留（analysis §3、§4） | `_retry` 流级持久，仅纯 ASCII 数字更新；`retry_hint()` 返回持久值；`SseEvent.retry` 为 dispatch 时刻快照，`has_retry()` = 快照非 0 | **已定**；`reset()` 是否清 retry 见 Q-04 |
| 4 | `feed` 注释"返回回调次数；致命错误返回 -1"，同时回调非 0 也转成 -1 | 计数语义与错误/中断语义混用，调用方无法判断是否应停止（analysis §3 高风险项） | 采用 **A 方案**：成功返回本次触发事件数（`>= 0`）；任何错误（行超限 / OOM / 回调中断）返回 `-1` 且置 `has_error()`；回调中断后本块剩余字节不再解析；ct-http 侧以 `feed < 0` 中断传输 | **已定**；B 方案否决（错误只能事后查 `has_error()`，与"中断必须立即停止解析"耦合弱）；`finish` 同口径见 Q-06 |

## 6 待确认

> 每条写清：现状与可选口径、**不确认会卡住什么**。

| 编号 | 待确认项 | 现状与可选口径 | 不确认会卡住什么 |
| --- | --- | --- | --- |
| Q-01 | `sse_event_copy(ev)` 是否纳入本包公开 API | 提案无此 API；analysis §3 把它列为"借用风险"的最小防线之一。口径 A：纳入并配释放函数；口径 B：不提供，只在文档要求调用方自行 `strdup`/拷贝 | 卡住 R-B-05 的验收是否存在；也卡住 R-B-04 防线强度（无 copy API 时负例只能证明"会失效"，不能给出正解）；并影响公开面清单 Q-02 |
| Q-02 | 公开 API 面最终清单 | 需求层已定"最小且可枚举"，但清单尚未逐条确认。候选：`new` / `on_event` / `max_line_bytes` / `feed` / `finish` / `has_error` / `error_msg` / `last_event_id` / `retry_hint` / `reset`（10 项），是否增删 | 卡住 R-E-01 的符号比对没有基线；后续任何 helper 改名都会变成破坏性变更却无法判定 |
| Q-03 | `max_line_bytes(n)` 的 `n` 含义 | 口径 A：`n` = 含结尾 NUL 的缓冲容量，内容上限 `n-1`（现有判据 `_line_len + 1 >= n` 自洽）；口径 B：`n` = 内容字节上限，需改判据为 `_line_len >= n` | 卡住 R-C-03 的 `n-1` / `n` / `n+1` 三组边界用例；卡住 README 该参数的可核对描述 |
| Q-04 | `reset()` 是否清空 `_retry` | 口径 A：新流则清（`reset` 后 `retry_hint() == 0`）；口径 B：保留，视为跨流重连建议 | 卡住 R-D-05 的验收；影响"复用 parser 做重连"时退避值是否被意外重置 |
| Q-05 | 事件级 data 总量上限是否本期纳入 | 提案只有行上限；口径 A：本期加 `max_event_bytes(n)` 一类上限；口径 B：明确"本期不主张"，只留行上限 | 卡住 R-C-04 是否成立；若不做，需在文档中写明"单事件可以无限累积"这一已知风险，否则内存安全验收不完整 |
| Q-06 | `finish()` 返回值是否与 `feed` 同口径（A 方案） | 提案写"返回回调次数；错误 -1"，与 `feed` 同类歧义；analysis 未单列 | 卡住 R-D-03 的验收；若两者口径不一致，调用方需要两套判断逻辑，集成成本上升 |
| Q-07 | 错误文本是否作为稳定契约 | 口径 A：文本精确稳定，测试精确比对；口径 B：只保证非 NULL，测试前缀匹配 | 卡住 R-D-02 的测试写法；也影响"行超限文本含可配置上限"这一判据能否成立 |

## 7 CT 语言能力依赖汇总

| 能力 | 本包用途 | 现状 | 阻塞等级 |
| --- | --- | --- | --- |
| 函数指针 + `pub typedef`（L11） | `SseEventCb` 跨模块导出 | 已支持 | 已支持 |
| 用户定义变参 + `va_list`/`vsnprintf` | 错误格式化（**自由函数**） | 已支持；**方法变参被硬拒** | 已支持（按 §4 #1 改口径） |
| `pub struct` + `impl` + `static` 方法 + `self->` | 主体类型与状态机 | 已支持 | 已支持 |
| 显式 `impl Drop` + `delete` | 缓冲释放 | 已支持（不生成字段递归 glue） | 已支持 |
| `own` 只认 `malloc`/`calloc`（L5） | `new()` 返回裸指针 | 已支持（显式 `delete` 绕行） | 已支持 |
| 方法级可见性 | 让 helper 真正私有 | 不支持 | **软阻塞**（`.ct` 内 `static` 自由函数绕行） |
| 借用检查 | 保证事件字段不逃逸 | 不支持 | **软阻塞**（契约 + 负例，不申请语言特性） |
| 工厂返回值可 `own` | 自动释放 | 不支持 | **软阻塞**（`delete` 已覆盖） |
| `Vec<char>` 零拷贝取元素（L9） | — | 不使用（改手动 `char *`） | 已支持 |
| 自定义 `[]`（L1 / phase40） | — | 不使用 | 已支持 |
| `defer` / `errdefer`（L8） | — | 不使用（改 `int` 返回码） | 已支持 |

**结论：按本文改后口径，硬阻塞 0 项。** 软阻塞 3 项（方法可见性、借用检查、工厂 `own`），均有不改语言的绕行方案，且都不构成对 CT 语言的新需求。

## 8 全局非目标

1. 不做 HTTP 传输、连接管理、chunk 读取（ct-http 负责）。
2. 不做 LLM 协议语义解析（ct-llm-sse 负责）。
3. 不做重连/退避策略（内核策略），只暴露 `retry_hint()` 与 `last_event_id()`。
4. 不做事件路由、多订阅、事件总线。
5. 不做字符编码转换（BOM 除外，且 BOM 本身待确认 Q-09）。
6. 不新增 CT 语言能力（借用检查、方法级私有、工厂 `own`、自定义 `[]` 均拒绝）。
7. 不提供线程安全保障。
